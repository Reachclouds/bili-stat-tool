  数据结构：

  @dataclass
  class TierConfig:
      name: str            # "第一档"
      threshold: int       # 累计播放量门槛
      pool: float          # 瓜分奖池总额(元)
      max_per_person: float # 单人最高瓜分(元)

  @dataclass

      tier_name: str
      nickname: str
      uid: int

      estimated: float     # 预估收益

  四、结算算法（严格按需求4步）

  输入: 档位配置(按门槛从低到高排序), UP主播放数据 [{nickname, uid, total_play}]

  对每个档位(独立计算):
    1. 准入筛选: 合格UP主 = {UP主 | total_play >= 档位.threshold}
    2. 权重统计: 达标总播放量 = Σ(合格UP主.total_play)
    3. 收益初算: 预估 = 档位.pool × (个人播放量 / 达标总播放量)
    4. 封顶校验:
       if 预估 > 档位.max_per_person:
         实发 = 档位.max_per_person
         溢出 = 预估 - 实发  (计入平台结余，不做二次分配)
       else:
         实发 = 预估

     奖池结算功能 — 实现计划

     Context

     在现有B站UP主播放量统计工具基础上，新增多档位奖池结算模块。核心结算机制：固
     定总奖池 + 按个人播放占比分配 + 单人收益封顶 + 溢出归平台。用户通过可视化界
     面配置档位参数，系统自动完成结算计算，结果持久化并可在Excel中导出。

     新增文件

     1. bili_stat/settlement.py — 结算引擎 + 持久化

     常量：
     - SETTLEMENT_CONFIG_FILE → ~/.BiliStatTool/settlement_config.json
     - SETTLEMENT_RESULT_FILE → ~/.BiliStatTool/settlement_result.json
     - DEFAULT_TIERS — 7档默认配置（门槛从低到高，奖池和封顶额逐档递增）

     持久化函数（复用 storage.py 原子写入模式）：
     - load_settlement_config() → list[dict]，文件缺失时返回默认配置
     - save_settlement_config(config) → tmp + os.replace 原子写入
     - load_settlement_result() → dict | None
     - save_settlement_result(result) → tmp + os.replace 原子写入

     核心算法 calculate_settlement(tiers, up_play_data) -> dict：
     1. 档位按 threshold 降序排列
     2. UP主按 views 降序排列
     3. 档位分配：每UP主归属到其达标的最高档位（一趟遍历，已分配者跳过）
     4. 逐档位执行4步结算：
       - 准入筛选：views >= threshold
       - 权重统计：达标总播放量 = Σ(成员views)
       - 收益初算：预估 = pool × (个人 / 总)
       - 封顶校验：if 预估 > max_per_person → 实发 = max_per_person，标记封顶
     5. 返回完整结算结果字典（含档位汇总 + 成员明细 + 溢出金额）

     辅助函数 aggregate_up_views(video_data, start_date, end_date) -> dict：
     - 输入：视频数据列表 + 日期范围
     - 按 publish date 过滤
     - 按 uid 聚合播放量（排除 excluded=True）
     - 返回 {uid: {"nickname": str, "total_views": int}}

     2. bili_stat/ui/settlement_dialog.py — 档位配置 + 结算预览对话框

     SettlementDialog(QDialog)，约 1100×750，使用 MAIN_STYLE。

     布局结构：
     VBoxLayout:
     ├── QGroupBox "数据筛选"
     │   ├── QDateEdit(start) / QDateEdit(end) — 视频发布日期范围
     │   └── QCheckBox "包含统计中视频" (默认勾选)
     ├── QTabWidget:
     │   ├── Tab "档位配置":
     │   │   ├── QTableWidget (editable, 4列:
     档位名称|门槛播放量|瓜分金额|单人上限)
     │   │   └── [添加档位] [删除选中] [▲上移] [▼下移] [恢复默认]
     │   └── Tab "结算预览":
     │       ├── 档位汇总表 (5列: 档位|门槛|瓜分金额|单人上限|奖池人数)
     │       └── UP主结算明细表 (8列:
     档位|UP主|UID|播放量|占比|预估收益|实际收益|是否封顶)
     └── [保存配置] [预览结算] [应用结算] [取消]

     数据流

     用户统计完成 → final_rank_data + raw_video_data_backup
       → 点击"奖池结算"
         → SettlementDialog 打开
           → 加载 settlement_config.json（可编辑）
           → 用户点击"预览结算"
             → 合并 daily_data + raw_video_data_backup
             → 按视频发布日期过滤
             → aggregate_up_views() 按UP主聚合
             → calculate_settlement() 执行4步结算
             → 展示预览结果
           → 用户点击"应用结算"
             → 保存 config → settlement_config.json
             → 保存 result → settlement_result.json
             → dialog.settlement_result = result
             → accept()
         → main_window.settlement_result = dialog.settlement_result
       → 用户点击"导出Excel"
         → export_excel(..., settlement_data=result)
         → 在Excel中生成第3个sheet

     不修改的文件

     - bili_stat/storage.py — settlement.py 内部复用原子写入模式，不耦合
     - bili_stat/config.py — 复用 get_app_data_dir()，结算文件路径在
     settlement.py 内定义
     - bili_stat/ui/styles.py — MAIN_STYLE 已覆盖所有需要的控件样式

     边界情况

     - 零达标UP主：预览表显示"无达标UP主"
     - 某档位仅1人达标：该人获得 min(pool, cap)，超出部分计为溢出
     - 空视频数据：aggregate 返回空 dict，calculate 正常返回无成员结果
     - 除零保护：达标总播放量为0时，占比和预估均为0
     - BV号去重：合并 daily_data 和 raw_video_data_backup
     时，后者优先（数据更新）
